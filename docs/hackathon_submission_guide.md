# 제5회 Agentic AI Hackathon with Google Cloud 제출 완벽 가이드

이 문서는 해커톤의 **개발 및 기술적 필수 요건**을 바탕으로 프로젝트의 기술 스택을 더욱 확장하여 심사위원의 가산점을 확보하는 전략과, **필수 제출물**을 완벽하게 준비하기 위한 단계별 가이드를 제공합니다.

---

## 1. 기술적 필수 요건 확장 전략 (가산점 극대화)

현재 ChronosLife는 필수 요건(Cloud Run, Gemini API, Cloud DLP, Ekispert MCP)을 충족하고 있습니다. 여기서 심사위원들에게 강렬한 인상을 남기고 기술적 완성도를 어필하기 위해 다음과 같이 스택을 확장할 수 있습니다.

### ① Google Cloud 인프라 & 선택 기술(Firebase) 확장
* **현재 상태**: 프론트엔드/백엔드 모두 로컬 또는 단일 Cloud Run에 의존.
* **확장 전략 (Firebase App Hosting 도입)**:
  * 해커톤 FAQ에서 공식적으로 인정한 **Firebase App Hosting**을 사용하여 Next.js 프론트엔드를 배포합니다.
  * 이를 통해 백엔드는 **Cloud Run**, 프론트엔드는 **Firebase**라는 서버리스 멀티-티어 아키텍처를 과시할 수 있으며, 선택적 활용 기술(Firebase) 가산점을 즉시 획득할 수 있습니다.

### ② Google Cloud AI 기술 심화 적용 (RAG & 음성)
* **현재 상태**: Gemini API(생성/중재) 및 Cloud DLP(보안) 사용 중.
* **확장 전략 1 (Vertex AI Vector Search)**:
  * 현재 `chief_governor.py`의 인생 헌법 RAG 대조를 단순 텍스트 주입에서 **Vertex AI Vector Search** 기반으로 변경하여 엔터프라이즈급 AI 아키텍처를 구성할 수 있습니다.
* **확장 전략 2 (음성 AI 결합)**:
  * Gemini Live 오디오 파이프라인(`gemini_live_session.py`)의 폴백이나 접근성 보조 수단으로 **Google Cloud Speech-to-Text (STT) / Text-to-Speech (TTS) API**를 파이프라인에 서브로 결합하면, 공식 지원 AI 기술 요건을 2~3개 이상 충족하는 강력한 포트폴리오가 됩니다.

### ③ 오픈 모델 (Gemma) 엣지 폴백 도입
* **확장 전략 (Gemma 활용)**:
  * Gemini API 장애(503/429) 시, 프라이버시 샌드박스의 PII 검출(Stage 1)을 Google Cloud에 배포된 **Gemma** 모델이나 로컬 온디바이스 모델을 통해 수행하는 '하이브리드 엣지 폴백' 시나리오를 추가하면 "가관측성과 보안성" 심사 기준에서 만점을 기대할 수 있습니다.

## 2. 필수 제출물 (Deliverables) 제작 가이드

마감일(2026년 10월 15일 23:59 JST)까지 제출해야 하는 4가지 필수 제출물의 제작 및 준비 가이드입니다.

### ① GitHub 리포지토리 연동 및 관리
심사위원(Google Developer Advocate, 마츠오 연구소 등)은 실제 코드를 열어보고 Mock 데이터 여부를 검증합니다.
* **준비 사항**:
  * `main` 브랜치에 있는 모든 `MOCK` 환경 변수 기본값을 `False`로 변경하거나 실제 API 키가 동작하도록 리포지토리를 정리합니다.
  * Zenn 대시보드에서 **GitHub App 연동**을 완료하고 `main` 브랜치를 제출 브랜치로 지정합니다.
  * **주의**: **10월 15일 이후 12월 1일까지 `main` 브랜치는 절대 수정(Push/Merge)해서는 안 됩니다** (자동 탈락 사유).

### ② 배포된 서비스 라이브 URL (Live Web URL)
네이티브 앱보다 반응형 웹(Web)이 심사 시 절대적으로 유리합니다.
* **준비 사항**:
  * 프론트엔드(Firebase App Hosting)와 백엔드(Cloud Run)의 도메인을 연결하고 CORS를 허용합니다.
  * 심사위원 접속용 **테스트 계정(ID/PW)** 및 3대 시나리오 프리셋(야간 충동 지출, 스타트업 이직, 연속 야근)이 **하드코딩이 아닌 실제 파이프라인**을 타도록 연결된 URL을 제출폼에 기재합니다.

### ③ 시스템 아키텍처 다이어그램
기술 스택이 어떻게 결합되었는지 한눈에 보여주는 가장 중요한 시각 자료입니다.
* **제작 팁**:
  * Google Cloud 공식 아이콘(Cloud Run, Firebase, Cloud DLP, Gemini)을 활용해 **[Excalidraw](https://excalidraw.com/)**, **[Draw.io](https://app.diagrams.net/)**, 또는 **[Google Cloud Architecture Diagraming Tool](https://cloud.google.com/architecture/icons?hl=ko)**로 고해상도 이미지를 제작합니다.
  * 단순한 블록 다이어그램을 넘어, *Layer 0 (Cloud DLP) → Layer 1 (Orchestrator) → Layer 3 (Governor)* 로 이어지는 데이터의 흐름과 '비식별화 보호 장막'을 시각적으로 강조해야 합니다.

### ④ 3분 시연 데모 영상 (YouTube 공개 링크)
3분은 매우 짧습니다. 기술적 복잡성보다 **"어떤 문제를 해결했는가"**와 **"결과가 얼마나 직관적인가"**에 집중해야 합니다.
* **영상 구성 스크립트 추천 (총 3분 / 180초)**:
  1. **[00:00 - 00:30] 문제 정의 (30초)**: 
     * 현대인의 의지력 고갈과 인지적 편향 설명. "1일의 치킨 결제와 30년 후 은퇴 지연 사이의 인과를 잇는다"는 슬로건 제시.
  2. **[00:30 - 01:20] Layer 0 DLP & Log-10 시연 (50초)**:
     * 실제 앱 화면에서 "아내 수진이", "신한은행"이 입력될 때 Cloud DLP가 이를 실시간으로 토큰화하여 방어하는 콘솔 화면(DevLogInspector)을 투명하게 공개.
     * 지출이 5단계 3중 궤적(선그래프)으로 전파되어 은퇴 시점을 지연시키는 시각적 임팩트 연출.
  3. **[01:20 - 02:20] 에이전트 위원회 & 헌법 중재 심의 (60초)**:
     * 스타트업 고연봉 이직 제안 프리셋 구동.
     * 재정(찬성) vs 건강/가족(반대)의 상충을 최고 중재관이 "주 52시간 조건부 승인안"으로 파레토 최적화하는 과정을 스켈레톤 UI와 함께 극적으로 렌더링.
  4. **[02:20 - 03:00] 액션(Ekispert) & 5컷 웹툰 마무리 (40초)**:
     * 번아웃 야근 감지 시 Ekispert API를 호출하여 "15분 힐링 녹지 환승로"를 처방하는 물리적 결합 증명.
     * 생성된 5컷 웹툰을 보여주며 "자율성, 가관측성, 보안성을 모두 갖춘 완벽한 LifeOS"로 마무리.
* **도구**: OBS Studio를 통해 고화질로 화면을 녹화하고, Vrew나 Descript를 활용해 반드시 **일본어 자막**을 크게 삽입하십시오 (심사위원 배려).
