### 1) 대회 핵심 배경 및 지향점
누구나 AI 에이전트를 쉽게 프로토타이핑할 수 있는 시대를 넘어, 이제는 **"실제 현업과 비즈니스 환경에서 믿고 쓸 수 있는가"**가 핵심 화두로 떠올랐습니다. 
자율적으로 동작하는 AI가 많아질수록 관리 범위를 벗어난 '야생 에이전트(野良エージェント)'의 보안 사고, 프롬프트 인젝션, 무단 도구(MCP) 호출, 통제 불능 문제가 발생합니다. 이에 따라 본 해커톤은 **가관측성(Observability), 보안성(Security), 거버넌스(Governance)**를 갖춘 '신뢰할 수 있는 에이전트'를 발굴하는 데 목적이 있습니다.

## 4. 참가 자격 및 기술 요건 (Rules & Technical Requirements)

### 1) 참가 자격
* **대상**: 일본 국내에 거주하는 만 18세 이상의 개인 또는 팀.
* **제외 대상**: 정부 기관 직원(프리랜서/겸업 포함 불가), 기업 대표 자격으로 참가하는 개인, 주최/스폰서사 임직원 및 관계자.
* *참고: Google Cloud Innovators 프로그램 사전 가입은 불필요.*

### 2) 개발 및 기술적 필수 요건 (Requirements)

1. **Google Cloud 애플리케이션 실행 환경 (1개 이상 필수)**:
   * Cloud Run, Cloud Run functions (구 Cloud Functions), Compute Engine, Google Kubernetes Engine (GKE), App Engine, Cloud TPU / GPU
   * *FAQ 확인 완료: Firebase App Hosting 및 Cloud Functions for Firebase 사용 시에도 실행 환경 조건 충족.*
2. **Google Cloud AI 기술 (1개 이상 필수)**:
   * Gemini Enterprise Agent Platform (구 Vertex AI - Model Garden, Vector Search 포함)
   * Gemini API (Google AI Studio를 통한 직접 연동 또는 Firebase経由 연동도 공식 인정)
   * Gemma, Nano Banana, Agent Development Kit (ADK)
   * Speech-to-Text / Text-to-Speech API, Vision AI, Natural Language AI, Translation AI
3. **선택적 활용 기술 (가산 및 특전)**:
   * Flutter, Firebase
   * Support 스폰서 기술: Ekispert API MCP 서버, YouCam API, GMI Cloud 등

### 3) 필수 제출물 (Deliverables)

1. **GitHub 리포지토리 연동**:
   * Zenn 대시보드 GitHub App을 통해 연동.
   * 공개/비공개 무관하나 심사용 기본 브랜치(Default branch)는 12월 1일까지 변경 금지.
2. **배포된 서비스 라이브 URL (Live Web URL)**:
   * Google Cloud 상에 실제 배포되어 접속 가능한 상태여야 함.
   * 인증이 필요한 경우 테스트 계정 ID/PW 및 심사위원이 즉시 확인할 수 있는 샘플 데이터를 사전 입력해 두어야 함.
3. **프로젝트 설명 및 시각 자료**:
   * 타깃 사용자, 해결하려는 핵심 과제, 솔루션 특징 요약문.

### ① [대형 기회] 동일 팀의 '복수 프로젝트 제출' 공식 허용
* **FAQ 명시 내용**:
  * *Q: 동일 멤버가 여러 프로젝트를 제출할 수 있나요?* $\rightarrow$ **"가능합니다. 대시보드에서 각각 프로젝트를 생성하여 개별 제출해 주십시오."**
  * *Q: 여러 프로젝트에 관여하면 심사에 불리한가요?* $\rightarrow$ **"불리하지 않습니다. 프로젝트 그 자체를 평가합니다."**
* **전략적 의미 (2-Track 동시 공략 가능)**:
  * 최우수상 타깃 B2B 엔터프라이즈 보안 프로젝트(`SentinelOps: StrayHunter`)와 우수상/특별상 타깃 라이프OS 거버넌스 프로젝트(`ChronosLife`)를 **동시에 개별 프로젝트로 제출**할 수 있습니다.
  * 동일한 Cloud Run 인프라 템플릿과 Google GenAI SDK를 공유하므로 적은 공수로 입상 확률을 2배로 극대화할 수 있습니다.

### ② [심사 리스크] "주요 기능이 모크(Mock)가 아님을 증명해야 함"
* **FAQ 명시 내용**:
  * *Q: 프로젝트 코드는 어느 수준까지 포함해야 하나요?* $\rightarrow$ **"주요 기능이 모크가 아니라 실제로 구현되어 있음을 알 수 있는 수준으로 리포지토리에 포함하여 제출해 주십시오."**
  * *Q: 연동된 코드 리포지토리는 어디에 쓰이나요?* $\rightarrow$ **"동작 확인 및 심사에 사용합니다."**
* **전략적 의미**:
  * 심사위원(Google Developer Advocate, 마츠오 연구소, GDE 등)이 깃허브 코드를 열어보고 **하드코딩된 더미 응답인지 실제 로직 및 API 연동인지 직접 검증**합니다.
  * 프롬프트 텍스트만 나열하는 형태는 탈락 위험이 높으며, Cloud DLP 토크나이저 모듈(`privacy_guard.py`)이나 Log-10 복리 계산기(`log10_engine.py`)처럼 **순수 파이썬/TypeScript 로직이 명확히 코드로 구현되어 리포지토리에 존재**해야 합니다.

### ③ [개발 공수 대폭 단축] AI Studio 직접 연동 & Firebase 환경 인정

## 8. 공식 FAQ 전수 카테고리별 총정리 (Complete FAQ Reference)

### 1) 엔트리 및 팀 빌딩 관련
* **Q: 엔트리 절차는 어떻게 되나요?**
  * A: 공식 페이지 '신청하기' 버튼을 눌러 Zenn 계정으로 로그인 후 엔트리합니다. 대시보드에 표시되는 참가자 정보 구글 폼(성명·소속 등)을 작성하면 정식 완료됩니다.

  * A: 필요합니다. 대표자와 팀원 전원이 각각 참가 등록을 마쳐야 합니다.

* **Q: 로컬 환경에서만 돌아가면 되나요? 클라우드 배포가 필수인가요?**
  * A: **Google Cloud에 실제 배포가 필수입니다.**

  * A: 직접 호출도 인정됩니다. 단, GCP 앱 실행 환경(Cloud Run 등) 1개 이상 사용 조건은 별도로 충족해야 합니다.

  * A: 제출 시점의 결과물을 기준으로 심사하므로 제출 후 수정은 엄격히 금지됩니다.
